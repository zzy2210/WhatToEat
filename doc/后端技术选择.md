# 后端技术栈选择与迁移规划

## 🎯 MVP阶段技术选择

### 选择 Rusqlite 的原因
- 数据模型相对简单（2个核心模型）
- 查询逻辑不复杂
- 本地应用，性能优先
- 符合KISS原则，快速开发

### 后续迁移到 Sea-ORM 的考虑
- 项目需要持续迭代
- 后续功能会更复杂
- 需要更好的类型安全和维护性
- 团队协作需要统一的数据访问方式

---

## 🏗️ 平滑迁移架构设计

### 关键原则
1. **数据库Schema保持一致** - 表结构设计时考虑Sea-ORM约定
2. **业务逻辑分层** - 数据访问层独立，便于替换
3. **渐进式重构** - 可以逐个模型迁移，两种方式共存

### 推荐的项目结构
```rust
src/
├── database/
│   ├── connection.rs          // 数据库连接管理
│   ├── models.rs             // 数据模型定义
│   ├── food_repository.rs    // 食物数据访问层（将来替换）
│   └── tag_repository.rs     // 标签数据访问层（将来替换）
├── services/
│   ├── food_service.rs       // 食物业务逻辑（保持不变）
│   ├── tag_service.rs        // 标签业务逻辑（保持不变）
│   └── recommendation_service.rs // 推荐算法（保持不变）
├── commands/
│   ├── food_commands.rs      // Tauri命令接口
│   ├── tag_commands.rs       // Tauri命令接口
│   └── recommendation_commands.rs
└── lib.rs
```

### 迁移步骤
1. **Phase 1 - MVP开发**
   - 使用Rusqlite实现repository层
   - 建立清晰的分层架构
   - 确保数据库schema兼容性

2. **Phase 2 - 准备迁移** 
   - 添加Sea-ORM依赖
   - 创建entity定义
   - 编写迁移脚本

3. **Phase 3 - 渐进迁移**
   - 逐个替换repository实现
   - 保持services和commands层不变
   - 测试功能一致性

4. **Phase 4 - 清理**
   - 移除Rusqlite相关代码
   - 优化Sea-ORM特性使用
   - 代码重构和优化

## 📋 数据库表结构设计

### 基于模型设计.md的表结构

```sql
-- 食物表
CREATE TABLE foods (
    uuid TEXT PRIMARY KEY,           -- UUID主键
    name TEXT NOT NULL,              -- 食物名称
    emoji_icon TEXT,                 -- emoji图标（可选）
    tag_uuids TEXT,                  -- 标签UUID数组（JSON格式）
    is_enabled BOOLEAN DEFAULT true, -- 是否启用
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 标签表  
CREATE TABLE tags (
    uuid TEXT PRIMARY KEY,           -- UUID主键
    name TEXT NOT NULL,              -- 标签名称
    emoji_icon TEXT,                 -- emoji图标（可选）
    score INTEGER NOT NULL,          -- 分数 -100 ~ +100
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 索引优化
CREATE INDEX idx_foods_enabled ON foods(is_enabled);
CREATE INDEX idx_tags_score ON tags(score);
```

## 🔄 迁移兼容性要点

### 数据类型映射
- `TEXT` → Sea-ORM的 `String`
- `INTEGER` → Sea-ORM的 `i32`
- `BOOLEAN` → Sea-ORM的 `bool`
- `DATETIME` → Sea-ORM的 `ChronoDateTimeUtc`
- `JSON数组` → Sea-ORM的 `Vec<String>` with `#[sea_orm(column_type = "Json")]`

### Repository接口设计
确保接口在两个实现中保持一致：
```rust
#[async_trait]
pub trait FoodRepository {
    async fn create(&self, food: CreateFoodRequest) -> Result<Food>;
    async fn find_by_id(&self, uuid: &str) -> Result<Option<Food>>;
    async fn find_enabled(&self) -> Result<Vec<Food>>;
    async fn update(&self, food: UpdateFoodRequest) -> Result<Food>;
    async fn toggle_status(&self, uuid: &str) -> Result<bool>;
}
```
